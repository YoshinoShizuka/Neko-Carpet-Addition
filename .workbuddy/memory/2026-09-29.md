## 第二轮：文案精简 + 统一配色（同日）

需求：① 换算行去掉「≈」；② 潜影盒模式物品描述太累赘要精简；③ 全仓库描述文字做可读性 / 高亮颜色审查。

### 核心结论：盒模式「累赘」的根因
`VoidWarehousePageContainer.shulkerDisplay` 是在**普通 lore（4 行）后面追加 3 行** = 7 行，
而被追加的「左键：取出 1 个 / 右键：取出一组」在盒模式下**根本不成立**（左键实际交出 1 盒）。
所以既冗余又误导 → 改成**按模式生成两套说明**（`Entry.display()` / `Entry.displayInBoxMode()`），
共用数据行、各用自己的操作行。盒模式 5 行、普通模式 4 行。

### 新文件：`VoidWarehouseText`（整个仓库文案/配色的单一出处）
语义色（按信息主次排序，各处只说语义、不自己挑颜色）：
- `VALUE` GOLD  = 核心数值（数量、盒/组/个换算）
- `ACTION` GREEN = 可执行操作（左键/右键）
- `FACT` AQUA  = 客观事实（容量、规则、当前模式）
- `COST` RED   = 代价与拒绝（消耗材料、会失败的情形）
- `NOTE` DARK_GRAY = 次要补充
- `ON` GREEN / `OFF` GRAY = 开关名字的开/关色
方法：`line(text, style)` / `name(text, Boolean on)` / `info(body)`（`[信息] `金色前缀）/ `count(BigInteger|long)`。
注意 `line` 收 ChatFormatting、`name` 收 Boolean，别混（编译会报「boolean 无法转换为 ChatFormatting」）。

### 顺手修掉的旧问题
- 潜影盒开关把「左键单击切换」写了两遍（开状态下第 4、5 行都是）→ 现在只 1 次；开 5 行、关 4 行。
- 数量排序开关 5 行 → 3 行。占位格 / 空位 2 行 → 1 行。
- 不可堆叠物品（max=1）换算行会输出无意义的「1 组」→ 门槛改为「够一组才算，
  max=1 时抬到够一盒（27）」，且 max=1 时不输出「组」这一级。
- 聊天提示原先一半带 `[信息]` 前缀一半不带 → 全部统一走 `VoidWarehouseText.info()`。
- `Menu.infoMessage()` / `Withdraw.info()` 两处重复实现 → 删掉，统一到 VoidWarehouseText。

### 自检（四版本全部 checks=29 failures=0）
新增断言：换算行不含「≈」；盒模式不含「取出 1 个 / 取出 1 组」（防误导回归）；
盒模式 5 行 / 普通 4 行 / 钻石剑 2 行；开关「左键」只出现 1 次；
**每行 lore 都必须有颜色**（`getStyle().getColor() != null`）—— 这是「统一配色」的硬保证。

### 踩坑
- `Nav` 不能整体复制到 26.1.x：26.1.x 是 `Items.RED_STAINED_GLASS_PANE`，26.2+ 才是
  `Items.STAINED_GLASS_PANE.red()`。回退替换时**注释整段必须排在代码单点替换之前**，
  否则单点替换会先改掉注释里的 `.red()`，整段就匹配不上了。
- 工具脚本移到 `.workbuddy/tools/` 后，`selfcheck_toggle.py` 里的 MODERN 路径要改成 `../..`（向上两级）。

### 产物
`dist/carpet-Neko-Addition-mc{26.3,26.2,26.1.1,26.1.2}-1.0.3.jar`（1.0.2 → 1.0.3）。

## 第三轮：适配 1.21.11（versions/1.21.11 从骨架到落地）

### 关键决策：用 Mojang 官方映射，不用 Yarn
`mappings loom.officialMojangMappings()`（而不是骨架里写的 Yarn）。
26.x 源码本来就是 Mojang 命名，换成 Yarn 会凭空多出几百处机械改名；
用官方映射后整包复制过来只有 **11 个编译错误 / 7 个 API 差异**。

### 构建接线改动
- `loom_version` 1.9.2 → **1.18.2**（仓库是 Gradle 9.7，1.9.2 对应 Gradle 8.x，配置阶段就废）
- `carpet_version` `1.21.11-1.4.194+v251223` → **`v260107`**。
  骨架写的 v251223 在 masa 上根本不存在；1.21.11 线上只有 `1.4.193+v251211` 与 `1.4.194+v260107`。
  查版本用 `https://masa.dy.fi/maven/carpet/fabric-carpet/maven-metadata.xml`
- `build.gradle` 里的 **`#` 注释全部改成 `//`**（Groovy DSL 不吃 `#`，第 1 行就报 Unexpected character）
- `settings.gradle` 打开 `include ':versions:1.21.11'`
- `fabric.mod.json`: minecraft `>=1.21.11`、carpet `"*"`；mixins json `compatibilityLevel` **JAVA_21**
- `mod_version` 1.0.1 → 1.0.3

### 7 处编译期差异（均已 javap 核对 1.21.11 merged jar）
1. `net.minecraft.util.Prediction` 不存在 → 删 import
2. `placeItemBackInInventory(rest, Prediction.SERVER_ONLY)` → `placeItemBackInInventory(rest)`

4. `ContainerInput.QUICK_CRAFT/.PICKUP` → `ClickType.QUICK_CRAFT/.PICKUP`（成员名一致）
5. `SavedDataType` 的 id：26.3 是 `Identifier`，1.21.11 是 **`String`**（构造器 `(String, Supplier, Codec, DataFixTypes)`）
6. `Items.STAINED_GLASS_PANE.red()` → `Items.RED_STAINED_GLASS_PANE`（1.21.11 无 `ColorCollection`）
7. `ItemContainerContents#nonEmptyItemCopyStream()` → **`nonEmptyItemsCopy()`**

## 附：误以为「commit 记录被清理」——排查结论

用户问「commit 记录好像被清理了」。彻查后确认 **没有清理**，证据：
- reflog 6 条全部是 `commit`，无 reset / rebase / checkout / gc 痕迹
- `git count-objects -v`：`in-pack: 0, packs: 0` → 从未 gc 过
- `git fsck --lost-found` 无 dangling commit；无 stash、无其他分支 / tag
- `.gitignore` 正常，没误伤源码

真实原因：**最新一轮（1.21.11）的成果根本没提交**，`versions/1.21.11/src/`
整个还是 untracked，所以在 git 里「看不到」。

### 排查 commit 是否被动过的固定套路
```
git reflog                 # 有没有 reset/rebase/gc
git count-objects -v       # in-pack/packs 为 0 = 从未 gc
git fsck --lost-found      # 悬空对象
git stash list / show-ref / branch -a
cat .gitignore             # 排除「被 ignore」这种假象
```
