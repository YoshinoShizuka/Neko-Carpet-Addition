# 多版本适配架构说明

本仓库已从「单模块、只支持 26.3」重构为「**单仓库 + 版本化目录**」的多版本结构，
目标是方便适配 Minecraft 1.15.2 ~ 26.3 的热门版本。

## 目录结构

```
carpet-Neko-Addition/
├── settings.gradle          # 根聚合：include 各版本子工程
├── build.gradle             # 根聚合（defaultTasks 'build'）
├── gradle.properties        # 根级共享属性（jvmargs 等）
├── gradle/ + gradlew        # 共享的 Gradle wrapper（9.7.0，服务 26.x）
│
├── common/                  # ★ 跨版本共享的纯逻辑（不引用 MC 版本类型）
│   └── src/main/java/neko/
│       ├── NekoConstants.java          # mod id / 分类名等常量
│       ├── automending/
│       │   ├── AutoMendingSettings.java  # 规则声明（只依赖 carpet-api 的 @Rule）
│       │   └── TranslationLoader.java    # Gson 读 lang json
│       └── voidwarehouse/
│           └── VoidWarehouseSettings.java
│
├── modern/                  # ★ 26.x 及以后（Minecraft 不再混淆）
│   ├── 26.3/                # 完整实现 + mixin + 资源（基准版本）
│   ├── 26.2/                # 与 26.3 仅差 1 处 API（Prediction）
│   ├── 26.1.1/              # 与 26.3 差 2 处 API（Prediction + ColorCollection）
│   └── 26.1.2/              # 同 26.1.1
│
└── versions/                # ★ 1.21.x 及更早（仍是混淆版本）
    └── 1.21.11/             # 骨架就绪，落地实现待做（Yarn 改写 40 个类 + 9 个 mixin）
        ├── build.gradle     # net.fabricmc.fabric-loom-remap + Yarn，Java 21
        ├── gradle.properties
        └── src/main/        # 版本专用实现 + mixin + 资源（待落地）
```

## 两条互斥的工具链

| | `modern/`（26.x） | `versions/`（≤1.21.x） |
|---|---|---|
| 混淆 | 不混淆（Mojang 官方命名） | 混淆，需映射 |
| Loom 插件 | `net.fabricmc.fabric-loom` | `net.fabricmc.fabric-loom-remap` |
| 映射 | 无需 mappings | Yarn 或 Mojang 官方映射 |
| Java | 25 | 21 |
| 依赖 | `implementation` | `modImplementation`（要 remap） |

> 这两条工具链**互斥**，无法塞进同一个 Gradle 项目，所以只能拆成两个子目录。
> 这也是「版本化源码集」在「混淆 vs 不混淆」这道分界线上的最终形态。

## 新增一个版本的步骤

1. 复制 `versions/<最接近的版本>/`（或 `modern/<最接近的版本>/`）为一个新目录；
2. 改它的 `gradle.properties`（minecraft / yarn / carpet / loader 版本）；
3. 在根 `settings.gradle` 里 `include` 一行；
4. 把 `src/main/java` 里引用 MC 类型的类，按目标版本的 API 改写（**用 javap 核对真实签名，绝不猜**）；
5. `./gradlew :<module>:build` 构建，跑一次 `runServer` 自检验证。

`common/` 层的代码无需任何改动——它只放不引用 MC 类型的纯逻辑。

## 已落地的 26.x 版本（不混淆，与 26.3 差异极小）

26.x 起 Minecraft 停止混淆，所以 26.1.1 ~ 26.3 之间只是「小版本 API 演化」，差异点很集中。
下表是逐个用 `javap` 核对后确认的实际差异（均已编译 + runServer 自检通过）：

| 版本 | Carpet 坐标（Modrinth id） | 与 26.3 的源码差异 |
|---|---|---|
| 26.2 | `maven.modrinth:carpet:bGrLxJ8v` | 仅 1 处：`placeItemBackInInventory` 无 `Prediction` 参数 |
| 26.1.1 | `maven.modrinth:carpet:ygtmLbO3`（26.1/26.1.1/26.1.2 共用一个包） | 2 处：① 无 `Prediction`；② 染色物品用独立字段 `Items.RED_STAINED_GLASS_PANE`（`ColorCollection` 是 26.2 才引入的） |
| 26.1.2 | 同上 | 同上（与 26.1.1 完全一致） |

### 26.x 内部 API 差异速查

| 能力 | 26.3 / 26.2 | 26.1.1 / 26.1.2 |
|---|---|---|
| 物品放回背包 | `placeItemBackInInventory(ItemStack, boolean, Prediction)` | `placeItemBackInInventory(ItemStack[, boolean])`，无 `Prediction` |
| 染色物品 | `Items.STAINED_GLASS_PANE.red()`（`ColorCollection`） | `Items.RED_STAINED_GLASS_PANE`（独立字段，16 色各一个） |
| 存档读写 | `ValueInput` / `ValueOutput` | 同左 |
| 聊天包 | `ServerboundChatPacket` / `handleChat` | 同左 |
| 漏斗 | `HopperBlockEntity#pushItemsTick` 等 | 同左（已核对，签名一致） |

> `ColorCollection` 把 16 种染色物品收进一个 `ColorCollection<Item>` 字段（`Items.STAINED_GLASS_PANE.red()`），
> 这是 26.2 引入的；26.1.x 仍是传统的 `Items.RED_STAINED_GLASS_PANE` 等 16 个独立字段。
> `Prediction` 枚举（`net.minecraft.util.Prediction`）是 26.3 新增的，26.2 及更早没有。

## 各版本间需要重点核对的 API（差异清单）

| 能力 | 26.3 | 1.21.x |
|---|---|---|
| 资源位置 | `Identifier` | `ResourceLocation` |
| 容器菜单 | `AbstractContainerMenu` | `ScreenHandler` |
| 大箱子菜单 | `ChestMenu` | `GenericContainerScreenHandler` |
| 打开界面工厂 | `MenuProvider` | `NamedScreenHandlerFactory` |
| 存档数据 | `SavedDataType` + Codec | `SavedData` + `load/save(CompoundTag)` |
| 聊天包处理 | `ServerboundChatPacket` / `handleChat` | 需 javap 核对 |
| 创造栏 | `CreativeModeTabs`（服务端可用） | 需核实服务端是否可用 |
| 数据组件 | `DataComponents` / `ItemLore` | 1.21.x 有，但 1.20.4 之前是 NBT |

> 1.15.2 ~ 1.16.5 是最大的鸿沟：尚无数据组件体系（纯 NBT）、无 `SavedData` 新 API、
> 且用 Yarn 映射的类名与 Mojang 命名差异极大，落地时需要单独评估。
