# 虚空仓库：滑翔时开界面两秒后被强制关闭

> 日期：2026-10-01 ｜ 影响版本：26.3 / 26.2 / 26.1.1 / 26.1.2 / 1.21.11（五版本同步）
> 产物：carpet-Neko-Addition 1.0.3（五版本全量重出）

## 1. 现象

> 在使用鞘翅滑翔时右键名称为虚空仓库的工作台，会在打开虚空仓库 GUI 界面后，两秒后被强制关闭 GUI 界面。

注意这个现象里最有价值的一条：**站着不动右键不会复现，只有「动起来」才会**。

## 2. 取证：界面是谁关的

### 2.1 服务端侧：原版每 tick 都会问一次「你还配打开这个界面吗」

`javap -c` 26.3 的 `ServerPlayer#tick()`（未混淆 jar），方法体第 38~65 字节：

```
38: getfield      containerMenu
42: invokevirtual AbstractContainerMenu.broadcastChanges:()V
45: getfield      containerMenu
49: aload_0
50: invokevirtual AbstractContainerMenu.stillValid:(Lnet/minecraft/world/entity/player/Player;)Z
53: ifne          68                    ← 有效就跳过
56: aload_0
57: invokevirtual closeContainer:()V    ← ★ 无效：服务端主动关界面
60: aload_0
61: getfield      inventoryMenu
65: putfield      containerMenu          ← 并退回背包界面
68: ...
```

`closeContainer()` 会给客户端发 `ClientboundContainerClosePacket`，所以玩家看到的就是
「界面自己被关掉了」—— 也就是玩家说的「被强制关闭」。

### 2.2 我们自己在 `stillValid` 里放了一条 8 格距离闸门

```java
// VoidWarehouseMenu#stillValid（修复前）
public boolean stillValid(Player player) {
    if (!VoidWarehouseSettings.voidWarehouse) return false;   // 规则关了
    if (!player.isAlive()) return false;                      // 死了
    if (!player.level().dimension().equals(this.openDimension)) return false;  // 跨维度
    return player.distanceToSqr(this.openPos) <= MAX_DISTANCE_SQ;   // ★ 8 格
}
```

`openPos` 是**打开界面那一刻玩家的坐标**（构造函数里 `opener.position()`），
`MAX_DISTANCE = 8.0`，注释写的是「对齐原版箱子的 8 格」。

于是链条完整了：

```
滑翔中右键开界面 → openPos = 开界面那一刻的位置
                 → 继续滑翔，位置不断远离 openPos
                 → 超过 8 格 ⇒ stillValid 返回 false
                 → 原版 tick 里 closeContainer() ⇒ 界面被强制关闭
```

**滑翔只是「最快突破 8 格」的方式，不是原因。** 疾跑（5.6 格/秒，约 1.4 秒）、
骑马、划船、矿车、鞘翅都一样会触发；站着不动才永远碰不到这条线。
玩家报的「两秒」对应的大约是 4 格/秒的位移速度。

## 3. 根因：这条闸门在语义上根本不成立

触发物是**手里的物品**，不是世界里的方块：

```java
// VoidWarehouseTrigger#isVoidWarehouse
if (stack.getItem() != Items.CRAFTING_TABLE) return false;
var customName = stack.getCustomName();
return customName != null && ITEM_NAME.equals(customName.getString());
```

只判「物品是工作台 + 自定义名精确等于「虚空仓库」」，**跟右键的是什么毫无关系** ——
对空气右键也能开（上一轮刚修好那条路），此时世界里压根没有「容器方块」可以走远。

而仓库的内容存在 `VoidWarehouseData`（挂在维度上的 `SavedData`）里，也不在任何方块上。

也就是说：**位置在语义上就是一个不相关的量**，拿它当闸门只会误伤。
「对齐原版箱子的 8 格」这个理由在这里是错的 —— 原版箱子有 8 格限制，
是因为它的内容物**物理上就在那个方块里**；虚空仓库不是。

## 4. 修复

去掉这条距离闸门，位置相关的字段一并删干净：

```java
// VoidWarehouseMenu（修复后）
@Override
public boolean stillValid(Player player) {
    // 规则被关掉时，已经打开的界面也要安全关闭
    if (!VoidWarehouseSettings.voidWarehouse) return false;
    if (!player.isAlive()) return false;
    // 切维度校验：跨维度时坐标没有可比性，直接让界面失效
    return player.level().dimension().equals(this.openDimension);
}
```

同时删除：`MAX_DISTANCE` / `MAX_DISTANCE_SQ` 两个常量、`private final Vec3 openPos` 字段、
构造函数里的 `this.openPos = opener.position()`、以及 `Vec3` 的 import。

**保留的三道闸门**（它们都不是位置相关的，都是真的该失效的情形）：

| 闸门 | 为什么必须留 |
|---|---|
| 规则 `voidWarehouse` 关闭 | 规则关掉后已打开的界面要安全关闭（`VoidWarehouseExtension#onTick` 也有一层兜底） |
| 玩家死亡 / 不存活 | 死了不该继续操作仓库 |
| 跨维度 | 跨维度坐标没有可比性，且仓库数据本身就是**按维度**存的 `SavedData` |

## 5. 自检

真实 26.3 服务端，模板 `.workbuddy/tools/VoidWarehouseGlideSelfCheck.java.template`。

**断言走的是原版契约本身**：`stillValid(Player)` 就是上面字节码里原版调用的那个方法，
所以直接断言它。假玩家没进实体表，真跑 `player.tick()` 会被重力带着位移，
反而让「站着不动」的对照组变得不确定 —— 所以这里不跑 tick，而是断言契约。

### 修复前（复现）

```
[D2] 走远 10 格 → stillValid=false（距离平方=100.0）        FAIL
[D3] 走远 200 格 → stillValid=false                        FAIL
[D4] 滑翔 40 tick（共 20 格）→ 全程有效=false，第 17 tick 失效   FAIL
[D6] 用下界玩家去判 overworld 开的界面 → valid=false         （闸门还在）
[D7] 死亡前后 valid=true → false                            （闸门还在）
[D8] 规则开关 valid=true → false                            （闸门还在）
SMOKE RESULT vw-glide/26.3 checks=16 failures=3
```

**D4 那一行就是玩家报的现象**：滑翔仿真里第 17 tick 界面失效。

### 修复后

```
[D2] 走远 10 格 → stillValid=true（距离平方=100.0）
[D3] 走远 200 格 → stillValid=true
[D4] 滑翔 40 tick（共 20 格）→ 全程有效=true
[D6] 用下界玩家去判 overworld 开的界面 → valid=false   ← 闸门保留
[D7] 死亡前后 valid=true → false                      ← 闸门保留
[D8] 规则开关 valid=true → false                      ← 闸门保留
SMOKE RESULT vw-glide/26.3 checks=16 failures=0
```

`failures=0` 连跑 **3 次**结果一致。

### 三组「有牙」的设计

| 组 | 断言 | 意义 |
|---|---|---|
| **D1** | 原地不动 40 tick 后 stillValid 仍为 true | 对照组。没有它，「走远就关」可能只是因为界面压根没打开 |
| **D5** | **原地滑翔** 40 tick 后仍有效 | 反证：证明 D4 断言的是「位移」，不是「滑翔这个状态」。滑翔状态本身从来不影响判定 |
| **D6/D7/D8** | 跨维度 / 死亡 / 规则关闭 ⇒ 失效 | 证明去掉的是距离这一条，三道真闸门一个没丢 |

修复前 `failures=3` 恰好是 D2/D3/D4 三组（都是距离），D1/D5/D6/D7/D8 全过 ——
**失败面精确地落在「距离」上，没有误伤**，这条断言是真的有牙。

## 7. 行为变化（玩家视角）

- 打开虚空仓库后**可以随意走动 / 飞行 / 滑翔**，界面不会再因为走远而自动关闭。
- 仍然会自动关闭的三种情况：**跨维度**、**死亡**、**服主把规则 `voidWarehouse` 关掉**。
- 关闭时不会丢东西：`removed()` 会把光标上的物品放回背包（塞不下就存进仓库）。

## 8. 教训

1. **「对齐原版 X」要先问一句：X 的那条约束为什么存在？** 原版箱子限 8 格，
   是因为内容物在那个方块里；虚空仓库的触发物是手里的物品、数据是 `SavedData`，
   位置是不相关的量。照抄形式而不看理由 ⇒ 把约束抄成了 bug。

2. **报的是「滑翔时」，真因往往是「位移」。** 玩家只能描述自己正在做的事
   （滑翔），但代码里根本没有人读滑翔状态。遇到「做某事时才复现」的 bug，
   先列出「这件事还带来了什么别的副作用」（这里是位移），再逐个排除 ——
   本轮用 D5 那一组反证就把「滑翔状态」干净地排除了。

3. **每 tick 生效的契约（如 `stillValid`）改动面很大，改之前先把调用它的
   原版代码找出来看一眼。** `javap -c` 打 `ServerPlayer#tick`，三行字节码就说明了
   「谁关的界面、关了之后还做了什么」，比猜快得多。

4. **删功能时要顺手把配套字段 / 常量 / import 一起删干净。** 留下一个没人用的
   `openPos` 字段，下一个人会以为还有人在用它。
