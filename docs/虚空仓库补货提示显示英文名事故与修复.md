# 虚空仓库补货提示显示英文名（泥土 → dirt）事故与修复

**日期**：2026-10-02
**报告人**：玩家（服务器实测）
**现象**：中键从虚空仓库补货后，聊天栏那条「取走 X 个 …」的提示里，物品名变成英文
（「泥土」→「dirt」）。**单人存档里正常**。

---

## 1. 根因：服务端把物品名提前「翻译」掉了

`ItemStack#getHoverName()` 返回的**不是文字，是一个可翻译组件**
（`{"translate":"block.minecraft.dirt"}`）。它的设计意图是
**发到客户端之后，由客户端按玩家自己的语言渲染**。

旧代码在服务端干了这件事：

```java
String name = outcome.sample().getHoverName().getString();   // ← 元凶
```

`getString()` 会用**当前进程**的那一份语言表（`net.minecraft.locale.Language`）
当场把组件解析成字符串，再把字符串发出去。而那份语言表的来源是：

```java
// net.minecraft.locale.Language（javap 实证）
static {
    DEFAULT_INSTANCE = loadDefault();     // 读 /assets/minecraft/lang/en_us.json
    instance         = DEFAULT_INSTANCE;
}
public static void inject(Language language) { instance = language; }   // 客户端启动时调用
```

- **单人存档**：客户端和服务端在同一个 JVM 里。客户端 `LanguageManager` 启动时会
  `Language.inject(玩家选的语言表)` —— 把这个静态单例换成了中文。
  于是**服务端的代码也算出了中文**，看起来一切正常（**这正是这个 bug 能活到现在的原因**）。
- **专用服务器**：没有任何客户端来 `inject`，单例一直是那份 `en_us`。
  同一个 `getString()` 就得到 `Dirt`，玩家的中文客户端只能照单全收。

> 已修好的一点是：**「在单人存档里看着没问题」不等于「对」**。
> 单人存档的客户端与服务端共用一份进程内状态，是最容易掩盖「服务端不该做的事」的场景。

## 2. 取证（离线自检里复现出来的那一幕）

自检在 `runServer`（专用服务端语义）里直接打印：

```
[diag] Language.getInstance() == DEFAULT_INSTANCE ? true
[diag] getOrDefault(block.minecraft.dirt) = 'Dirt'
[diag] 旧写法 getHoverName().getString() = 'Dirt'              ← 玩家的现象，离线复现
[diag] 注入中文语言表后渲染: '虚空仓库 取走 64 个 泥土，仓库剩余 1,234 个'   ← 修完的效果
[diag] 旧写法那版消息（同样注入中文语言表）渲染: '虚空仓库 取走 64 个 Dirt，仓库剩余 1,234 个'  ← 反证
```

最后两行是本事故的核心对照：**同一个「客户端语言表」下，新写法渲染出「泥土」，
旧写法仍是「Dirt」** —— 因为旧写法已经把文字烧死在服务端了。

## 3. 修法

保持组件原样发出去，让本地化发生在客户端：

```java
player.sendSystemMessage(VoidWarehouseText.info(VoidWarehouseText.RESTOCK_PREFIX,
        VoidWarehouseText.body("取走 ")
                .append(VoidWarehouseText.key(VoidWarehouseText.count(outcome.takenCount())))
                .append(VoidWarehouseText.body(" 个 "))
                .append(VoidWarehouseText.body(outcome.sample().getHoverName()))   // ← 组件，不是字符串
                .append(VoidWarehouseText.body("，仓库剩余 "))
                .append(VoidWarehouseText.key(VoidWarehouseText.count(outcome.remaining())))
                .append(VoidWarehouseText.body(" 个"))));
```

新增 `VoidWarehouseText.body(Component)`：`text.copy().setStyle(灰 + 正体)` ——
把物品名整个套成正文样式（它自带的样式在这条提示里不该冒出来），但**内容一个字不解析**。

自检把这条链路钉了四层：

1. 新消息里物品名仍是 `TranslatableContents`，key = `block.minecraft.dirt`；
2. 过一遍 `ComponentSerialization.STREAM_CODEC`（真实的发包编码）后仍是可翻译组件、无残留字节；
3. 走**原版渲染链路**（`getVisualOrderText()` → 逐字符的有效样式）断言颜色/正体都对；
4. **反证**：把 `block.minecraft.dirt → 泥土` 的假语言表 `Language.inject` 进去，
   新消息渲染出「泥土」，而旧写法那版消息仍是「Dirt」。

## 4. 同类风险清单（以后别再踩）

凡是**要发给玩家看的 Minecraft 名字**（物品、方块、实体、附魔、状态效果……），
都不能在自己这一侧 `getString()` / `Component.translatable(...).getString()`：

| 场景 | 正确做法 |
|---|---|
| 聊天提示里的物品名 | 直接把 `getHoverName()` 组件 append 进去 |
| 自定义包里的物品名 | 传 `Identifier`（或整份组件），**不要传解析后的字符串** |
| 日志 / 控制台 | 这里用 `getString()` 是对的 —— 服务端日志本来就只有 en_us |
| 需要「按玩家语言」的字符串比较 | 用组件/key 比较，别比翻译结果 |

判据很简单：**这句话最终是给玩家的眼睛看的，就必须保持组件形态直到客户端**。

> 顺带解释另一个常见误解：「服务端 `getString()` 会得到 `block.minecraft.dirt` 这种原始 key」
> —— 只有在语言表**完全没加载**时才会。原版 `Language` 的静态初值就是
> `loadDefault()`（en_us），所以正常情况下拿到的是 `Dirt`，看起来「像个正常的英文名」，
> 更难被当成 bug。

## 5. 同轮的两处文案改动

| 改动 | 位置 |
|---|---|
| 盒模式物品格的 `消耗：潜影壳 ×2 + 箱子 ×1` 整行删除 | `VoidWarehouseData.buildDisplay` 的 `boxMode` 分支 |
| 中键补货提示前缀 `[信息] ` → `虚空仓库 `；「仓库剩余 X 个」的 X 改亮绿 | `PrinterRestockNetwork.notifyTaken` |

材料账本身没变，说明保留在「潜影盒模式」开关的 tooltip 上（`VoidWarehouseNav.shulkerToggle`）。
